# Janus soundness audit — round 4

Fourth independent review of the claim: *if `janus verify` (or `verify-batch`, or consumer
`--proof-root` verification) prints `Verified`, everything it reports to the user (the printed
statement, the disclosed definitions, `janus explain`, `verified.json`) is an exact and honest
account of a theorem that holds for the actual bytes of this binary under the documented
semantics.*

Rounds 1–3 closed the statement *type* (round-trip and `checkInstArgs`) and, in round 3, inline
instances in the *bodies* of disclosed proof-local defs. This round looks at **the report
channels**: what the user actually reads, and whether each item is confirmed by a trusted check.
Rows are in `audit/round4/` (`attacks/`, `run-round4.sh`) and `cmd/janus/round4_test.go`.

Severity, as in earlier rounds: **critical** = a misleading account prints `Verified`;
**high** = a reported item the user relies on is missing or unconfirmed; **low** = hygiene.

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| D1 | **critical** | disclosed definition bodies were printed but never round-tripped: a numeral's type (and fun-binder types) could be hidden | **BROKEN → fixed** |
| D2 | **high** | `verify` and `explain` never display the disclosed definitions, although the statement's meaning depends on them | **BROKEN → fixed** |
| D3 | low | report text (names, statement, Lean error text in batch FAIL lines) reached the terminal with control characters intact | **fixed** (defence in depth) |
| D4 | residual | definitions whose print is not re-elaborated (universe-polymorphic `match` auxiliaries) | tagged `[not round-tripped]` |
| P1 | pre-existing | round-2 row MEDIUM-1 (`DFRepro.memmove_backward_rep_copies_forward`) prints `Verified` at HEAD `ee8887e`, without this branch's changes | reported, row not changed |

## Enumeration

### (A) What the user reads, and where it comes from

| Output | Generated by | Data source | Confirmed by |
|---|---|---|---|
| `Verified: <thm>` | `printVerified` (Go) | auditor record `name` | theorem kind/module check in the auditor |
| Module, Entry, Binary + SHA-256 | `printVerified` | `identity.json`, re-`check`ed binary | Go extraction re-check (trusted) |
| Proof path | `printVerified` | Go side | proof bytes re-read and compared |
| Consumer / Dependency / Build lines | `printVerified` | Go consumer pinning | `deps.go` pinning |
| Dependency constants | `printVerified`, `explain` | auditor `external` | `checkExternal` |
| Framework, Sandbox, Lean | `printVerified` | Go side | framework pin, sandbox self-test |
| Axioms | `printVerified`, `explain` | auditor `collectAxioms` | Go allow-list |
| Kernel replay | `printVerified`, `explain` | Go replay | `leanchecker` |
| **Statement** | auditor `printFaithful` | clean environment | `checkInstArgs` + round-trip |
| **Definitions** | auditor (was a bare `ppExpr`) | clean environment | round 3: `checkInstArgs`; **round 4: round-trip (D1)**. Before D2 it was shown nowhere but the JSON |
| `statementExplicit` | auditor, `pp.explicit` | clean environment | not round-tripped; JSON only, informational |
| `explain` text | `explain.go` | `verified.json` (re-read from disk), `identity.json` | the hash rows; the JSON itself is not authenticated (see below) |
| `verify-batch` PASS/FAIL lines | `batch.go` | report, or diag text (may contain Lean error text from the untrusted proof) | — (D3) |
| `verified.json` fields | `writeReport` | everything above, plus `timestamp`, `janusRoot`, `janusCommit` | `timestamp`, `janusCommit` (+`dirty`) are informational |

**`verified.json` is not self-authenticating.** `explain` re-reads it from disk and re-hashes the
binary, `Extracted.lean`, `identity.json` and the proof, but anyone who can write the file can
rewrite `statement` or `definitions`; nothing signs it. That is documented intent ("rerun janus
verify to re-establish the result"), and consumers should treat the JSON as a record, not as
evidence. Recorded, not changed.

### (B) Inputs the trusted side reads after untrusted code has run

* the proof's compiled `.olean`/`.ilean`/`.olean.private` bytes: pinned by SHA-256, imported with
  `loadExts := false` and no initializers, kernel-replayed (the olean loader itself is TCB, round 2);
* the auditor's stdout line, located by a per-run random marker the proof never sees (round 2);
* Lake/Lean stdout/stderr and exit codes from the sandboxed build: used only for diagnostics, and
  echoed into FAIL messages (D3 sanitizes them for the terminal);
* the replay cache: read-only inside the sandbox, keyed on bytes (round 2);
* the environment: `JANUS_SANDBOX`/`JANUS_CACHE_DIR` come from the operator's process, not the proof;
* timestamps: written, never trusted for a decision.

### (C) Lean features that can make a term read differently from its meaning

| Feature | Statement type | Disclosed def bodies |
|---|---|---|
| inline/non-canonical instances (`HMul`, `OfNat`, `GetElem`, `Membership`, `HPow`, `Bind`/`Monad` in `do`) | `checkInstArgs` + round-trip | `checkInstArgs` (round 3) + round-trip (D1) |
| numerals: `OfNat`/`OfScientific`, type hidden | round-trip with `pp.numericTypes` retry | **was unchecked → D1** |
| fun-binder types (`fun x => …`, `∃ x, …`) | round-trip | **was unchecked → D1** (`pp.funBinderTypes` retry) |
| coercions | `pp.coercions.types` + round-trip | `pp.coercions.types` + round-trip (D1) |
| `Decidable` in `decide`/`if`, in hypotheses too | `Decidable p` is a subsingleton, so any instance gives the same `decide`/`if`; inline ones are rejected anyway | same |
| `@[reducible]`/`abbrev` defs as instances, including class aliases (`abbrev T := HMul …`) | `instArgOk` unfolds reducible heads down to the literal, which is rejected | same |
| `let`- or lambda-bound instances | `instArgOk` rejects `let` fvars and non-inst-implicit binders | same |
| proof-local notation, macros, unexpanders, delaborators | the print happens in a clean environment that never imports the proof | same |
| structures/inductives declared in the proof file | `collectLocalDefs` accepts only `def`/`theorem` | — |
| proof-local theorems and instance lemmas | theorems allowed (only the type matters, and it is round-tripped by D1); instances rejected | same |
| string/char literals | printed escaped by `String.quote` | same |
| names containing control characters (`«…»`) | terminal display: D3 | D3 |
| quotients | `Quot.*` primitives are core; a dependency `quotInfo` is rejected by `checkExternal` | — |

The `Decidable`, reducible/alias, `let`/lambda-binder, structure and notation rows are code-reading
conclusions from `Janus/Tools/Audit.lean`, not new live repros. I did not add rows for them, and
I did not do new model-level (instruction-semantics) work this round.

## D1 (CRITICAL, BROKEN → fixed): disclosed definitions were not round-tripped

Round 3 added `checkInstArgs` to disclosed bodies and noted that "a fuller version would also
round-trip each disclosed body". Without that round-trip the disclosure is printed with default
options and nothing confirms that its text means the body. Printing hides type information the
statement printer recovers by its round-trip and `pp.numericTypes` retry:

```lean
def wide : Prop := (256 : BitVec 8) ≠ 0 ∨ True
```

was disclosed as `Proof.wide : Prop := 256 ≠ 0 ∨ True`, which reads at `Nat`. At `BitVec 8`, `256`
is `0`. A disclosed definition used as a *hypothesis* can therefore read as trivially true while
being false, and the reader gets no warning. That is the same class as round-3 R1: the
disclosure is the reader's only definition of a name in the statement. (The row
`audit/round4/attacks/D1_def_numeral_type.lean` keeps the hypothesis harmless with `∨ True` and
checks only how it is printed.)

**Fix** (`Janus/Tools/Audit.lean`, `termRoundTrips` + `discloseDef`): every disclosure is
re-parsed and re-elaborated in the clean environment. The printed type must elaborate to a type
kernel-defeq to the real one, and for a def the printed value, elaborated against the real type,
must be kernel-defeq to the real value (elaborator `isDefEq`, then confirmed by `Kernel.isDefEq`,
as in the statement round-trip). The plain print is tried first, then one with `pp.numericTypes`
and `pp.funBinderTypes`. The row now reads
`Proof.wide : Prop := (256 : BitVec (8 : Nat)) ≠ (0 : BitVec (8 : Nat)) ∨ True`.

## D2 (HIGH, BROKEN → fixed): the definitions were never shown

`verifiedReport.Definitions` was written to `verified.json`, but `printVerified` (verify, and
the consumer path, which uses it) and `explain` printed only the statement. `explain` says
"the guarantee is exactly this statement", yet a statement like `s'.regs 0 = Proof.f x y`
carries its meaning in `Proof.f`, which the user was never shown. **Fix:** both now print a
"Proof-local definitions used by the statement (part of its meaning)" block.

## D3 (LOW, fixed): terminal control characters in report text

Lean names written with `«…»` can contain arbitrary characters, and `verify-batch` FAIL lines
echo Lean error text produced from the untrusted proof. Such text reached the terminal
unfiltered, so ANSI or bidi-override sequences could make the displayed report differ from the
JSON. **Fix:** `termSafe` (`cmd/janus/verify.go`) renders C0/C1 controls (except newline and tab),
DEL and the bidi overrides/isolates as `\u{…}` in every human-facing line of `verify`, `explain`
and `verify-batch`. `verified.json` keeps the exact strings (JSON escapes them). Test:
`TestTermSafe`.

## D4 (residual): definitions that cannot be read back

Universe-polymorphic definitions are not re-elaborated; in the shipped examples these are only
the `match_1` auxiliaries of structurally recursive defs (`A64IndexByte`'s `indexOf.match_1`, amd64
`Sum`'s `sumFrom.match_1`). The compiled `Nat.brecOn` bodies of `indexOf`/`sumFrom` and their
`._f` helpers *do* round-trip. A print that cannot be read back for some other reason falls back
the same way. Such definitions are still disclosed, with the annotated print (`pp.numericTypes`,
`pp.funBinderTypes`) and an explicit `[not round-tripped: read with care]` tag rather than being
presented as confirmed. Inline instances in them are still rejected by the round-3 check. A
complete fix would disclose such a def's equation lemmas (`f.eq_1`, …), which are ordinary
statements and can be round-tripped like the theorem type.
